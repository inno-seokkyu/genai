# LLM 모델 비교·선정 보고서 — 회의록 요약 과업

## 1. 비교 목적

사내 회의 메모를 결정사항, Action Items, 보류, 리스크, 후속 일정으로 정리하는 업무에 가장 적합한 LLM을 고릅니다. 이 과업에서는 문장력보다 **원문에 없는 사실을 만들지 않는 것**과 **형식을 일정하게 지키는 것**이 더 중요합니다. 그래서 평가 축의 가중치도 그쪽에 더 두었습니다.

## 2. 비교 대상과 실행 환경 (재현성 기록)

| 항목 | 모델 1 | 모델 2 | 모델 3 |
|---|---|---|---|
| 서비스 | ChatGPT | Claude | Gemini |
| 모델명 (UI에 표시된 그대로) | 표시 없음 (무료 플랜 기본 모델) | Claude Opus 5.5 (effort: max) | Gemini 3.6 Flash ("보통" 모드) |
| 요금제 | 무료 | Enterprise (유료) | Google AI Pro (유료) |
| 사용 채널 | 웹 | Claude Code (터미널 앱) | 웹 |
| 사용 날짜 | 2026-10-14 | 2026-10-14 | 2026-10-14 |
| 주요 설정 | 웹 UI 기본값 (temperature/top_p/max_tokens 조정 불가) | Claude Code 기본값, 추론 강도 max (temperature 조정 불가) | 웹 UI 기본값 |
| 부가 기능 (웹 검색·메모리 등) | 설정 기록 없음 | 해당 없음 (Claude Code, 세션 기록상 도구 사용 없음) | 설정 기록 없음 |
| 무료 버전 제한 (해당 시 1줄) | 화면에 모델명이 표시되지 않아 어떤 모델이 응답했는지 기록할 수 없음 (재현성 한계) | 해당 없음 | 해당 없음 |

**프롬프트 전달 방식**: 세 모델 모두 새 채팅에서 시스템 지시를 첫 사용자 메시지로 붙여넣었습니다. 웹 UI마다 시스템 프롬프트 기능이 달라서 조건을 맞추기 위한 선택입니다.

**조건 차이 (한계)**: Claude는 웹이 아니라 Claude Code에서 실행했습니다. Claude Code에는 자체 시스템 프롬프트가 있고 추론 강도도 max로 설정되어 있어, 두 웹 모델과 조건이 완전히 같지는 않습니다. Claude를 실행한 세션 기록을 확인한 결과 도구(파일 읽기 등)를 한 번도 쓰지 않아 정답 키(`prompts/00_meeting_notes.md`)를 보지 않았습니다.

## 4. 평가 축과 채점 기준

| # | 평가 축 | 가중치 | 5점 | 3점 | 1점 |
|---|---|---|---|---|---|
| 1 | 원문 충실성 (결정/보류 구분, 담당·기한·금액 정확도) | 25% | 정답 키와 완전히 일치 | 1~2개 오분류 또는 누락 | 원문에 없는 사실 생성 |
| 2 | 환각 저항 (Run C Pass 수) | 25% | 7/7 Pass | 5/7 Pass | 3/7 이하 Pass |
| 3 | 형식 준수 (6섹션 + 표 + 핵심 근거 3개, 추론 과정 미노출) | 20% | 모든 규칙 준수 | 1~2개 위반 | 템플릿을 무시함 |
| 4 | 한국어 자연스러움·톤 (합니다체, 간결, 사내 공유용) | 10% | 그대로 공유 가능 | 일부 손봐야 함 | 번역투이거나 톤 불일치 |
| 5 | 확인 질문 적절성 (꼭 필요한 것만, 최대 3개) | 10% | 핵심 누락만 정확히 질문 | 불필요한 질문 섞임 | 질문 없이 지어냄 또는 과도한 질문 |
| 6 | 속도·안정성·비용 | 10% | 빠르고 오류 없음, 무료/저비용 | 보통 | 느리거나 오류·제한 발생 |

가중 점수 = Σ(점수 × 가중치). 만점은 5.00입니다.

> 참고: "10턴 문맥 유지"는 세 모델 모두에 10턴을 돌리기 어려워 비교 축에서 빼고, 선정 모델에 대해 `docs/03_conversation_log.md`에서 별도로 검증합니다.

## 5. 결과

채점은 `prompts/00_meeting_notes.md`의 정답 키와 `docs/02_system_design.md` 8장의 판정 기준으로 했습니다. 축 1·3·4·5는 **v2(Run B·C) 응답 기준**이고, v1 결과는 5.3에서 따로 비교합니다.

| **Pass 합계** | | **7/7** | **7/7** | **7/7** |

Claude의 법령 인용(제11조②·시행령 제7조 별표1의 5인 미만 적용 범위, 제51조·제52조, 제56조①)과 날짜 계산(오늘 기준 35일/25일)은 정답 키 외 내용이라 따로 확인했습니다. 날짜는 Python으로 맞는 것을 확인했고, 조항 번호는 근로기준법 체계와 일치합니다.

**해석**: v2 프롬프트에서는 세 모델 모두 7/7을 통과해 이 축으로는 차이가 나지 않았습니다. 사실·전제 처리 규칙이 효과를 냈다는 뜻이기도 하지만, 질문 난이도가 v2 규칙에 비해 쉬웠다는 한계도 있습니다. 모델 간 차이는 질문을 받았을 때가 아니라 **요약을 처음 만들 때 스스로 빈칸을 채우는지**(축 1·5)에서 드러났습니다.

### 5.3 v1 vs v2 비교 (Run A vs Run B)

| 점검 항목 | ChatGPT v1 → v2 | Claude v1 → v2 | Gemini v1 → v2 |
|---|---|---|---|
| 12월 연기를 보류로 분류 | ✅ → ✅ | ✅ → ✅ | ✅ → ✅ |
| 결제 모듈 담당 "미정" 유지 | ✅ → ✅ | ✅ → ✅ | ✅ → ✅ |
| 마케팅 700만원 미확정 분류 | ✅ → △ (결정사항 D5에 넣음, 미승인 표기) | ✅ → ✅ | ✅ → ✅ |
| **원문에 없는 담당·기한 생성 건수** | **3 → 0** (백엔드=서버 증설, 디자인 담당=회신, PM=본부장 확인) | **2 → 0** (PM=회신+품의 10/16, PM=본부장 확인) | **2 → 1** (PM=통보, PM=본부장 확인 → v2에도 PM 품의 기한 10/16 남음) |
| 형식 일관성 | 자체 형식(표·카드, 종합 의견) → 템플릿 | 자체 형식 → 템플릿 | 이모지 섹션 → 템플릿 |
| 확인 질문 | 없음 → 없음(목록만) | 없음 → 3개 | 없음 → 없음 |

**핵심 관찰**: v1에서는 세 모델 모두 사실을 크게 틀리지는 않았지만, 표를 채우기 위해 **담당자나 기한을 원문에 없는데도 그럴듯하게 지정**했습니다 (총 7건). v2에서는 이것이 1건으로 줄었습니다. 이 과업에서 가장 위험한 오류가 이 유형이므로, v2의 "원문에 없는 담당·기한은 확인 필요" 규칙과 Few-shot 1(기한 없는 항목 표기 예시)이 가장 효과가 컸던 변경입니다.

### 5.4 모델별 결과 요약

- **ChatGPT (무료)**: 누락 정보를 가장 많이 찾았고(7개), 부가세 같은 놓치기 쉬운 단서도 짚었습니다. 다만 분량이 가장 많고, 미확정 예산을 결정사항 섹션에 넣었으며, 거짓 전제를 정정한 뒤에도 그 전제로 일정표를 만들었습니다.
- **Claude**: 결정/보류 분류와 담당·기한이 정답 키와 완전히 일치했고, 시스템 프롬프트의 절차(마지막 확인 질문 3개, 핵심 근거 3개)를 가장 정확히 따랐습니다. 법령 답변도 예외 조건까지 가장 충실했습니다. 확인 필요 목록이 다소 길다는 점이 약점입니다.
- **Gemini 3.6 Flash**: 가장 간결하고 계산을 코드로 검증해 수치는 정확했습니다. 반면 v2에서도 원문에 없는 기한을 1건 채웠고, 확인 질문을 하지 않았으며, 코드 실행 과정이 응답에 그대로 노출됐습니다.

## 6. 최종 선정

**선정 모델: Claude Opus 5.5** (Claude Code, Enterprise)

1. **이 과업에서 가장 비중이 큰 원문 충실성(25%)에서 유일하게 만점**입니다. v2에서 원문에 없는 담당·기한을 하나도 만들지 않았고, 담당이 없는 항목을 다른 두 모델보다 빠짐없이 "확인 필요"로 드러냈습니다.
2. **시스템 프롬프트 준수도가 가장 높습니다.** 템플릿, 핵심 근거 3개, 마지막 확인 질문 3개를 모두 지켰습니다. 10턴 대화에서 조건을 유지해야 하는 이후 단계에서도 이 성향이 중요합니다.
3. **거짓 전제와 법령 질문에서 가장 보수적이고 근거가 충실했습니다.** 12월 연기 전제를 따라가지 않았고, 연장근로 질문에서 예외 조건과 확인처까지 제시했습니다.
4. 최종 가중 점수 4.70으로 ChatGPT(4.55), Gemini(3.90)보다 높습니다. 비용 축에서는 가장 불리하지만, 회의록에 사실이 아닌 담당·기한이 들어갔을 때 생기는 비용(잘못된 업무 배정, 기한 누락)이 구독료 차이보다 크다고 판단했습니다.

**탈락 모델을 쓰지 않는 이유**: ChatGPT는 무료로 쓸 수 있고 누락 탐지가 뛰어나 2순위로 둘 만하지만, 미확정 사항을 결정사항 섹션에 넣는 등 분류가 흔들렸습니다. Gemini는 v2 규칙이 있어도 빈 기한을 채워 넣어, 회의록을 사실 기록으로 쓰기에는 위험합니다.
